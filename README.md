# ♿ WCAG 2.2 AA Accessibility Auto-Audit

Dockerコンテナ上で **[Pa11y](https://pa11y.org/)** を動かし、ローカルのHTMLファイルに対して WCAG 2.2 AA 準拠のアクセシビリティ監査を全自動で行うツールです。

---

## ✨ 主な特徴

- **🖥 ヘッドレスブラウザによる正確な監査**  
  単なるソースコードのテキスト解析ではありません。裏側でChromiumブラウザを立ち上げてDOMを完全にレンダリングするため、JavaScript実行後の状態やCSS適用後のコントラスト比なども実機同様に正確にチェックします。
- **📊 リッチで直感的なHTMLレポート**  
  エラー（Error）、警告（Warning）、通知（Notice）をタブやアコーディオンでスッキリ整理した、専用のグラフィカルなレポートを出力します。
- **🔍 ワンクリックで解決策へアクセス**  
  専門的な英文エラーメッセージを維持しつつ、各エラーのWCAG達成基準（例: 1.4.3）についてワンクリックでGoogle検索できるリンクを自動生成します。

---

## 🛠 技術スタック

* **Docker / Docker Compose:** 実行環境のコンテナ化
* **Pa11y (Node.js):** アクセシビリティ自動監査のコアフレームワーク
* **axe-core & HTML CodeSniffer:** 高精度な2つの検査エンジン（ランナー）を併用
* **Chromium:** ヘッドレスブラウザ（DOMのレンダリング、CSS/JSの評価）
* **Shell Script (Bash):** 実行フロー（ビルド〜監査〜ブラウザ表示）の全自動化

---

## 🚀 クイックスタート

本ツールは、ターミナルから **たった1つのコマンド** を叩くだけで「ビルド → 監査 → レポート表示」までを全自動で行います。

### 1. ターゲットの設定 (`.env`)
ルートディレクトリにある `.env.example` をコピーして `.env` ファイルを作成し、テストしたいフォルダやファイル名を設定します。

```bash
cp .env.example .env
```

**.env の設定例**
```env
# 監査対象のHTMLファイルが入っているローカルマシンのパス
HTML_SOURCE_DIR=../source/seikatsu_test/html

# 監査したいファイル名（コンマまたはスペース区切りで複数指定可能）
TARGET_FILES=index.html, about.html, https://example.com
```

### 2. 監査の実行
以下のスクリプトを実行するだけで、すべて完了します。

```bash
./check_wcag.sh
```

**💡 このスクリプトが全自動で行うこと：**
1. Dockerコンテナのビルド（常に最新状態を維持します）
2. `.env` に記載された全ファイルのアクセシビリティ監査を実行
3. **監査完了後、Macの標準ブラウザを自動で起動し、結果レポートを表示**

---

## 📁 複数ファイルの一括テストについて

`.env` の `TARGET_FILES` に複数のファイル（例: `index.html, about.html`）を指定して実行した場合、テスト終了後に**「レポート一覧ページ（目次）」**が1つだけ自動生成され、ブラウザでパカッと開きます。

これにより、ブラウザのタブが大量に開くのを防ぎ、一覧ページからゆっくり各ページの結果を確認することができます。
